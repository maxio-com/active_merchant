# Decision realizations — Test Gateway as a real gateway, M1

How this repo realized the engineering decisions from
`mxd-artifacts/epic/test-gateway-v1/02-milestone-M1/decisions.md`. One entry
per mechanism choice or deliberate departure, keyed by the decision's `E<n>`
number. The reasoning for the decisions themselves lives in that file.

## E1 — Network-error cards raise like a real network failure

**Intent preserved:** cards and tokens ending `0028`, `0036`, `0044` raise
`ActiveMerchant::ConnectionError` (timeout, SSL, reset) on purchase, authorize
and verify.
**Mechanism:** the messages come from ActiveMerchant's own
`NetworkConnectionRetries::DEFAULT_CONNECTION_ERRORS`, the strings it raises on
a real network failure, and `triggering_exception` is an instance of the
matching class (`Timeout::Error`, `OpenSSL::SSL::SSLError`, `Errno::ECONNRESET`).
These are the plan's "today's messages": Conduit's `lib/gateway_behaviors.rb`
(`TimeoutBehavior`, `ConnectionResetBehavior`, `SSLErrorBehavior`) raises the same
three raw exceptions inside a faked `ssl_post`, and ActiveMerchant's
`NetworkConnectionRetries` turns them into `ConnectionError` with these strings
(read in Conduit by the engineer, 2026-11-05; Conduit is outside this repo).
**Accepted in:** #261
**Plan correction:** drafted 2026-11-05 · Phase 1 AC names ActiveMerchant's own messages; dated line under E1 · mxd PR not opened

## E1 / E3 — `53433` still purchases successfully

**Intent preserved:** legacy references keep today's outcomes.
**Departure:** read literally, the last-digit rule sends a purchase on `53433`
(last digit 3) to a gateway error. The code keeps today's special case, so a
bank account stored with today's `53433` authorization can still be charged
(E10). No card or `bogus_` token can reach it.
**Accepted in:** #261

## E1 / E7 — What every response carries

**Intent preserved:** responses carry the amount, the card's last four and the
authorization in their params.
**Mechanism:** amounts keep today's keys (`paid_amount`, `authorized_amount`);
`last4` and `authorization` are added, and a failed response carries
`authorization: nil` and `error`. `verify` no longer returns today's
`billingid: '1'`, which was a copy of store's.
**Accepted in:** #261
**Plan correction:** drafted 2026-11-05 · Phase 1 AC 9 restated per operation (void no amount, refund and capture no card, bank accounts as today) · mxd PR not opened

## E2 — `BogusGateway` changed in place

**Intent preserved:** one gateway named `bogus` everywhere.
**Mechanism:** today's public constants stay, including
`UNSTORE_/CAPTURE_/VOID_/REFUND_ERROR_MESSAGE`, which the gem no longer uses:
Conduit's `ChargifyTestGateway` subclasses this class and may reference them.
EMV cards and card `credit`, which the plan does not mention, keep today's rules
behind the live-Site check.
**Accepted in:** #261
**Plan correction:** drafted 2026-11-05 · Phase 1 gains an AC that purchase and authorize on an EMV card keep the amount rule, behind the live-Site check · mxd PR not opened

## E4 — `live_site` is checked first

**Intent preserved:** no operation except unstore runs without an explicit
`live_site: false`.
**Mechanism:** `requires!(options, [:live_site, true, false])` runs before any
dispatch, so EMV, bank-account and network-error paths are gated the same way.
`credit` with a String reference delegates to `refund` first, which checks it.
**Accepted in:** #261

## E5 / E6 — The vault token

**Intent preserved:** store returns `bogus_<site_id>_<8 hex>_<last4>` and needs
a Site id.
**Mechanism:** the token is returned as both `authorization` and
`params['billingid']`, the field today's legacy tokens `"1"`/`"2"` come from.
A blank `site_id` (`nil`, `''`) raises the same `ArgumentError` as a missing
one, because `requires!` only checks that the key exists and would otherwise
mint `bogus__<hex>_<last4>`.
**Accepted in:** #261

## E7 — Transaction ids

**Intent preserved:** every successful transaction gets a unique `bogus_txn_`
authorization; refund, capture and void always succeed.
**Mechanism:** `bogus_txn_` + `SecureRandom.hex(8)` (16 hex characters), not
the 8 in the plan's example. Unlike the vault token, these ids are not scoped by
Site or card, and at 8 hex characters the chance of some collision reaches 50%
at about 77,000 transactions across all test Sites. Refund, capture and void
each return a new id; void no longer echoes the reference in its params.
**Accepted in:** #261

## E11 — The `custom-188` line, referenced by branch until release

**Intent preserved:** the change ships on a branch off `v1.60.0-custom-188`, so
M1 and M2 need no Faraday 2 upgrade, and it reaches master.
**Departure:** nothing is tagged or merged during M1–M2. Conduit (Phase 3) and
chargify (M2) reference this branch by `git` + `branch:` in their Gemfiles, and the
engineer tests chargify by hand on those refs. At release the engineer tags the
branch head `v1.60.0-custom-188.1` (not master's squash commit, which carries
square.rb 43) and merges it, then bumps, tags and merges Conduit, then bumps and
merges chargify.
**Accepted in:** #261
**Plan correction:** drafted 2026-11-05 · Phase 2 and Phase 3 tag criteria, release order in Risk + rollback, the M2 dependency line, dated line under E11 · mxd PR not opened

## Review dispositions

### `lib/active_merchant/billing/gateways/bogus.rb:156` — store of a blank card number mints `bogus_<site_id>_<hex>_`
**Raised as:** P3, bugs lens, in the pre-PR review for #261.
**Why it isn't:** E1 decides that store fails only when the last digit is 3,
so any other number stores and fails when charged — the plan's own example is
`5555 5555 5555 4444`. A blank number follows the same rule: the token keeps its
Site and random part, and a purchase on it raises `Billing::Error`. Before this
change a blank number raised on store only because the old rule raised for most
numbers, not because of a blank-number guard.
**Would become real if:** a caller is shown to store blank numbers on purpose
(Conduit's re-store on update, E9, or Advanced Billing), at which point store
should reject them rather than mint a token that cannot be charged.
